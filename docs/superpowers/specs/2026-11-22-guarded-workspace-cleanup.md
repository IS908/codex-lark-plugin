# Guarded managed scratch cleanup (#387)

The v2.20.0 preview is advisory. Add a separately enabled, default-off maintenance pass under the existing Lark instance lock, before durable workers or ingress start. Startup must not enter the cleanup path in dry-run mode. Only plugin-owned scratch is in scope. The normal task store, project directories, caches, toolchains, formal artifacts, retry inputs, and legacy storage are never reclamation targets.

Check the configured retention age and capacity policy, and report blocked or partially observed sweeps. Use the same eligibility rules as the preview, but recompute from the authoritative ledger and the current pinned filesystem. A preview result, expired lease, directory name, or age alone does not grant permission. Keep executed Linux runs and unsupported hosts protected unless there is actual independent process evidence.

Reserve a per-run SQLite cleanup claim against the current allocation, baseline, and liveness observation. Persist the original pinned identity, a generated quarantine slot, state, timestamps, and bounded outcome codes. Once claimed, reject later scratch handoffs and dependency-install reservations, including compatible old SQLite writers; artifact reads remain independent. Use a dedicated WAL connection with FULL or stronger synchronization and macOS fullfsync, serialize against all durable writes, invalidate observations after same- or other-connection writes, and verify that the runtime already holds its global process lock.

Record intent before any move. Move into an owner-only, same-volume quarantine using pinned directory descriptors and an atomic no-replace rename. Verify and flush the changed directory entries before advancing the journal. Recheck the resulting identity and full preservation baseline before deleting. Reconcile the physical identity and recorded state on restart. When identities, metadata, mount policy, or references cannot be verified, do not purge or overwrite anything. Never scan quarantine names to adopt or delete unregistered data. A completed claim is a tombstone, not permission to recreate a removed run's scratch. Document that purge is not recoverable and that operators must not externally edit the maintenance tree during a sweep.

Tests must exercise two independent SQLite connections and process restart, interrupted claim/move/purge, lease and delivery changes, retry and artifact independence, path replacement, nested changes and symlink/alias rejection, disabled and legacy compatibility, and retention/capacity limits. Only disposable fixtures may be mutated for verification.
